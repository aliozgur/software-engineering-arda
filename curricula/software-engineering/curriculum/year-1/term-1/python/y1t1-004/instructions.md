# Python Fundamentals II: Errors, Files and Tests

**Task ID:** `y1t1-004`  
**Estimated effort:** 12 hours  
**Module:** Python

## Why this task exists

Treat errors and tests as normal parts of engineering rather than afterthoughts.

This is an apprenticeship task, not a content-consumption checkbox. Reading or watching material is only preparation.
Completion requires evidence that you can apply and explain the ideas.

## Authoritative resources

- **Harvard CS50P - Introduction to Programming with Python** (primary): https://cs50.harvard.edu/python/

Use the linked course/documentation as the primary source. You may use additional sources, but record them in your
learning notes and prefer primary documentation over tutorial aggregation sites.

## Work to complete

1. Study exceptions, libraries, unit tests, file I/O and regular expressions in CS50P.
2. Build a CLI that imports structured data from a text/CSV file, validates it and writes a report.
3. Write pytest tests for happy paths, boundaries and invalid inputs.
4. Introduce three bugs intentionally and document how tests expose them.

## Required evidence

- Git history showing incremental work
- README or technical note explaining the result
- Executable code/configuration when the task includes implementation
- Reflection notes answering the task questions
- AI disclosure entry when AI materially influenced the work

Where code is produced, submit a repository URL plus an immutable commit/tag reference when possible. Do not submit
only screenshots of code.

## Acceptance criteria

- [ ] Automated tests run with one command.
- [ ] At least 12 meaningful tests exist.
- [ ] Invalid files do not crash with an unexplained stack trace.
- [ ] README documents input format and error behavior.

The mentor may request a live explanation, modification or failure demonstration before approval. Passing automated
tests alone is not proof of understanding.

## Reflection

Answer these in your own words after doing the work:

1. Which bugs were easiest and hardest to test?
2. When should an exception be caught versus allowed to propagate?
3. What makes a test brittle?

Also record:

- What took longer than expected?
- What would you practice again?
- What remains unclear?
- Which artifact best proves that you learned the objective?
