Proposed live review questions

To probe understanding of the environment and README

1. “Walk me through your `README.md` as if I’m on a fresh machine. What exact steps would I take, and what assumptions are you making about my OS and installed tools?”
2. “Open `bootstrap.sh` and explain, line by line, what it does and what side effects it has on my system.”
3. “If `bootstrap.sh` fails halfway through, how would you recommend I recover? Is it safe to run it again?”

To probe shell and commands understanding

4. “Using only a terminal, show me how you would:
   - Confirm your current directory,
   - Find where your shell config file lives,
   - And edit it to add something to your PATH.”
5. “Show me how to find all running processes matching `python` and explain what each part of the command you use is doing.”
6. “Demonstrate redirecting both stdout and stderr from a command into:
   - a new file,
   - then appending further output to the same file.”
7. “What’s the difference between `export EDITOR=code` typed directly into the shell and adding the same line to your shell config file? When would you use each?”
8. “Explain the practical difference between `>` and `>>`. Can you show me a small example that illustrates this difference?”

To probe PATH and environment understanding

9. “You’ve run `echo $PATH`. How would you:
   - Add `~/bin` to your PATH permanently,
   - Verify that the change worked in a new shell?”
10. “If `which git` returns a path you don’t expect, how would you investigate which config or installation put it there?”

To probe process and tooling awareness

11. “Suppose a process is misbehaving and using too much CPU. How would you:
   - Find its PID,
   - Inspect what command started it,
   - And then terminate it from the command line?”
12. “Without using a GUI, how would you check what version of Python your editor is using for a given project, and how could you change that?”

To probe Git usage and safety

13. “Show me your commit history for this repo. How did you decide when to make each commit? If you were redoing it, would you change anything about your commit strategy?”
14. “If you accidentally committed a secret to this repo and pushed it, what steps would you take to remove it properly and mitigate the impact?”

To probe understanding of secrets and dotfiles

15. “What types of information should never live in a public `dotfiles` repo? How do you keep your configuration reusable without exposing secrets?”
16. “Do you have any mechanism (e.g., `.gitignore` or separate private files) to keep machine-specific or secret configuration out of this repo? Walk me through it.”

To probe reflection and learning

17. “What part of working primarily from the terminal felt most unfamiliar or uncomfortable, and how did you address that?”
18. “After doing this task, what are two shell techniques you didn’t use before but now find valuable? Can you show me an example of each on your machine?”
